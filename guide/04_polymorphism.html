Тема 04

Полиморфизм

Один интерфейс — множество реализаций. Как один вызов работает по-разному для разных типов объектов.

Что такое полиморфизм

Полиморфизм

Способность объектов разных классов реагировать на один и тот же вызов метода по-разному. Дословно: «много форм» (от греч. poly + morphe).

В C++ полиморфизм бывает нескольких видов:

  • Динамический (runtime) — виртуальные функции. Выбор реализации происходит во время выполнения.
  • Статический (compile-time) — шаблоны и перегрузка функций. Выбор происходит при компиляции.

Виртуальные функции и vtable

Когда функция помечена virtual, компилятор создаёт таблицу виртуальных функций (vtable). Каждый объект содержит скрытый указатель на vtable своего реального класса.

Как работает vtable
class Figure {
public:
    virtual double calc_area() const = 0;
};

class Circle : public Figure {
public:
    double calc_area() const override { return M_PI * r * r; }
};

class Triangle : public Figure {
public:
    double calc_area() const override { /* формула Герона */ }
};

// Полиморфный вызов — тип выбирается в runtime!
Figure* f1 = new Circle(...);
Figure* f2 = new Triangle(...);

f1->calc_area();  // → вызов Circle::calc_area()
f2->calc_area();  // → вызов Triangle::calc_area()

// Массив фигур — один цикл для разных типов!
std::vector<Figure*> shapes = { f1, f2, new Circle(...) };
for (auto* s : shapes)
    std::cout << s->calc_area() << std::endl;

Абстрактные классы и чисто виртуальные функции

Чисто виртуальная функция (= 0) не имеет реализации в базовом классе. Класс с хотя бы одной такой функцией — абстрактный: нельзя создать его объект напрямую.

Абстрактный класс
class Function {
public:
    virtual double calculate(double x) const = 0; // чисто виртуальная
    virtual void   print(double x)    const = 0; // чисто виртуальная

    // Реализация через calculate() — полиморфный алгоритм
    double integrate(double a, double b, int n = 1000) const {
        double h = (b - a) / n, sum = 0;
        for (int i = 0; i < n; i++)
            sum += (calculate(a + i*h) + calculate(a + (i+1)*h)) * h / 2;
        return sum;
    }
};

// Function f;  // ОШИБКА — нельзя создать объект абстрактного класса
Parabola p(1, 0, 0);  // OK
p.integrate(0, 1);   // Вызовет Parabola::calculate() внутри!

Виртуальный деструктор — обязательно!

Если удалять объект через указатель на базовый класс, нужен виртуальный деструктор. Иначе вызовется только деструктор базового класса, а деструктор производного — нет. Утечка памяти!

Виртуальный деструктор
class Figure {
public:
    virtual ~Figure() = default;  // ← ОБЯЗАТЕЛЬНО если есть virtual
};

class Circle : public Figure {
    double* data; // динамическая память
public:
    ~Circle() { delete[] data; }
};

Figure* f = new Circle(...);
delete f;  // Без virtual ~Figure() — вызовется только ~Figure()!
           // С virtual ~Figure() — вызовется ~Circle(), потом ~Figure()
Правило
Если класс имеет хотя бы одну виртуальную функцию — деструктор тоже должен быть виртуальным. Все три класса из репозитория — Figure, Function, Figure (шахматы) — следуют этому правилу.

Полиморфизм в действии: геометрические фигуры

Посмотри как используется полиморфизм в geometrical_figures/main.cpp:

geometrical_figures/main.cpp
// Единый вектор для хранения разных фигур
std::vector<Figure*> figures;
figures.push_back(new Circle<double>({0,0}, 5.0));
figures.push_back(new Triangle<double>({0,0}, {3,0}, {0,4}));
figures.push_back(new Rectangle<double>({0,0}, {4,3}));

// Один цикл — разные реализации calc_area()
double total = 0;
for (auto* fig : figures) {
    std::cout << "Площадь: " << fig->calc_area() << "\n";
    total += fig->calc_area();
}
std::cout << "Итого: " << total << "\n";

// Освобождение памяти
for (auto* fig : figures) delete fig;

Тест для самопроверки

6 вопросов
Вопрос 1

Что такое vtable (таблица виртуальных функций)?

Компилятор создаёт vtable для каждого класса с виртуальными функциями. Каждый объект хранит скрытый указатель (vptr) на vtable своего реального класса. При вызове виртуальной функции используется этот указатель для нахождения нужной реализации.
Вопрос 2

Можно ли создать объект абстрактного класса?

Абстрактный класс (с чисто виртуальными функциями) нельзя инстанцировать напрямую. Компилятор отвергает Figure f;. Но можно иметь указатель или ссылку: Figure* f = new Circle(...);
Вопрос 3

Почему виртуальный деструктор обязателен для базового класса с виртуальными методами?

Без virtual деструктора: Figure* f = new Circle; delete f; вызовет только ~Figure(), а ~Circle() — нет. Если Circle выделял память, она утечёт. Виртуальный деструктор обеспечивает правильную цепочку вызовов.
Вопрос 4

Что происходит, если производный класс НЕ переопределяет чисто виртуальную функцию?

Если хотя бы одна чисто виртуальная функция не переопределена, производный класс тоже считается абстрактным. Его нельзя инстанцировать, пока все pure virtual методы не будут реализованы.
Вопрос 5

Чем отличается вызов obj.method() от ptr->method() для виртуальных функций?

Полиморфизм (динамическая диспетчеризация) работает через указатели или ссылки на базовый класс: Figure* f = new Circle; f->calc_area();. Если использовать объект напрямую, компилятор знает точный тип и вызовет нужный метод статически.
Вопрос 6

В каком файле репозитория демонстрируется паттерн "Template Method" — базовый класс определяет алгоритм, вызывая абстрактные методы?

В Function: метод integrate() реализован в базовом классе и использует метод calculate(), который является чисто виртуальным. Наследники (Parabola, Hiperbola и т.д.) определяют только calculate(), а интегрирование они получают бесплатно.
