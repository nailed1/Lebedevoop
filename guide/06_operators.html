Тема 06

Перегрузка операторов

Как заставить свои классы работать с +, -, *, /, ==, << и другими операторами.

Что такое перегрузка операторов

В C++ можно определить, что происходит при применении стандартных операторов к объектам своего класса. Это делает код читабельным и естественным:

Без перегрузки vs. с перегрузкой
// Без перегрузки — некрасиво
Rational r1(1, 2), r2(1, 3);
Rational r3 = r1.add(r2);

// С перегрузкой — как обычная математика
Rational r3 = r1 + r2;
if (r1 < r2) std::cout << r1 << " меньше " << r2;

Арифметические операторы: Rational

Класс Rational — лучший пример для изучения перегрузки. Разберём паттерн += и +:

class_Rational/rational.cpp — паттерн +=  и +
// Составной оператор += — изменяет объект, возвращает ссылку
Rational& Rational::operator+=(const Rational& r) {
    // Проверяем переполнение перед операцией
    if (will_mul_overflow(num, r.den) ||
        will_mul_overflow(r.num, den) ||
        will_add_overflow(num * r.den, r.num * den))
        throw std::overflow_error("Overflow in Rational::operator+=");

    num = num * r.den + r.num * den;
    den = den * r.den;
    simplify();  // НОД — сокращение дроби
    return *this;
}

// Бинарный оператор + — создаёт новый объект, не изменяет this
// Реализован через += — лучшая практика!
Rational Rational::operator+(const Rational& r) const {
    Rational result = *this;  // копия
    result += r;               // используем уже написанный +=
    return result;
}
Паттерн: + через +=
Реализуй += с основной логикой, потом + через копию и +=. Это убирает дублирование кода. То же для -=/-, *=/*, /=/÷.

Операторы сравнения

class_Rational/rational.cpp — сравнение
bool Rational::operator==(const Rational& r) const {
    // Дроби уже сокращены (в simplify), значит достаточно сравнить num и den
    return num == r.num && den == r.den;
}

bool Rational::operator<(const Rational& r) const {
    // a/b < c/d ⟺ a*d < c*b (при b,d > 0)
    return num * r.den < r.num * den;
}

bool Rational::operator!=(const Rational& r) const {
    return !(*this == r);  // через уже написанный ==
}

bool Rational::operator>(const Rational& r) const {
    return r < *this;  // через уже написанный <
}

Операторы ввода/вывода (<< и >>)

Эти операторы нельзя сделать методом класса (левый операнд — ostream, не наш класс). Делаем свободной функцией — другом класса:

class_Rational/rational.h и rational.cpp
// В заголовке — объявление как friend
class Rational {
    friend std::ostream& operator<<(std::ostream& os, const Rational& r);
    friend std::istream& operator>>(std::istream& is, Rational& r);
};

// Реализация оператора <<
std::ostream& operator<<(std::ostream& os, const Rational& r) {
    if (r.den == 1)
        os << r.num;             // целое число — без знаменателя
    else
        os << r.num << "/" << r.den;
    return os;  // возвращаем os для цепочки: cout << r1 << r2
}

// Реализация оператора >>
std::istream& operator>>(std::istream& is, Rational& r) {
    char slash;
    is >> r.num >> slash >> r.den;  // читаем "3/4"
    r.simplify();
    return is;
}

Оператор [] и преобразование типов

// Возвращаем ссылку — можно использовать как l-value: arr[0] = 5
int& Array::operator[](int index) {
    if (index < 0 || index >= size)
        throw ArrayException("Index out of bounds");
    return ptr[index];
}

// class_Rational/rational.h — операторы преобразования типов
class Rational {
public:
    // Неявное преобразование в int (отбрасывает дробную часть)
    operator int() const { return (int)(num / den); }

    // Явное (explicit) преобразование в double
    explicit operator double() const { return (double)num / den; }
};

Что нельзя перегрузить
Нельзя перегрузить: ::, ., .*, ?:, sizeof, typeid. Нельзя придумывать новые операторы — только перегружать существующие.

Тест для самопроверки

5 вопросов
Вопрос 1

Почему operator<< реализован как свободная функция, а не метод класса?

При cout << r левый операнд — cout типа ostream. Если бы оператор был методом класса Rational, то левым операндом был бы объект Rational. Поэтому используем свободную функцию, которую делаем другом (friend) для доступа к приватным полям.
Вопрос 2

Зачем operator+= возвращает Rational&, а не void?

Возврат *this по ссылке позволяет цепочки: a += b += c. Кроме того, это соответствует поведению встроенных операторов для примитивных типов.
Вопрос 3

В чём лучшая практика реализации operator+?

Реализуй сложную логику в +=, а + пусть создаёт копию и вызывает +=. Это устраняет дублирование: при изменении логики правишь только одно место.
Вопрос 4

Что такое explicit operator double() const?

explicit предотвращает неявное преобразование. Без explicit: Rational r(1,3); double d = r; — сработает автоматически, что может быть неожиданно. С explicit: нужно явно написать double d = (double)r;
Вопрос 5

Что вернёт operator[] в классе Array: int или int&? Почему?

Возврат int& (ссылки) позволяет использовать оператор как l-value: arr[0] = 5. Если бы возвращался int, то arr[0] = 5 присваивало бы значение временной переменной, а не элементу массива.
