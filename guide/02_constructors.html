Тема 02

Конструкторы и деструкторы

Жизненный цикл объекта: как он создаётся, копируется и уничтожается.

Жизненный цикл объекта

Каждый объект проходит три этапа:

  1. Создание — вызывается конструктор, инициализируются поля
  2. Использование — вызываются методы, объект живёт
  3. Уничтожение — вызывается деструктор, освобождаются ресурсы

Виды конструкторов

1. Конструктор по умолчанию

Вызывается без аргументов. Если не написать — компилятор сгенерирует автоматически (но он ничего не инициализирует!).

class_array/array.cpp
Array::Array() {
    ptr = nullptr;
    size = 0;
    capacity = 0;
}

// Использование:
Array a;  // вызывает конструктор по умолчанию

2. Конструктор с параметрами

class_array/array.cpp
Array::Array(int sz) {
    size = sz;
    capacity = sz;
    ptr = new int[capacity];
    for (int i = 0; i < size; i++)
        ptr[i] = 0;  // инициализируем нулями
}

// Использование:
Array a(10);  // массив на 10 элементов

3. Конструктор копирования

Создаёт новый объект как копию существующего. Важен при работе с динамической памятью — иначе два объекта укажут на один и тот же участок памяти (проблема поверхностного копирования).

class_array/array.cpp — глубокое копирование
Array::Array(const Array& arr) {
    size     = arr.size;
    capacity = arr.capacity;

    // Выделяем НОВЫЙ блок памяти — не копируем указатель!
    ptr = new int[capacity];
    for (int i = 0; i < size; i++)
        ptr[i] = arr.ptr[i];  // копируем данные
}

// Использование:
Array a(5);
Array b = a;  // вызывает конструктор копирования
Array c(a);   // то же самое
Проблема поверхностного копирования
Если не написать конструктор копирования, компилятор скопирует указатель, а не данные. При удалении одного объекта второй останется с висячим указателем — это undefined behavior.

4. Список инициализации

Более эффективный способ инициализировать поля — через список инициализации:

Список инициализации
// Без списка инициализации (сначала вызов конструктора по умолчанию,
// потом присваивание — два шага)
Rational::Rational(long long n, long long d) {
    num = n;  // присваивание после инициализации
    den = d;
    simplify();
}

// Со списком инициализации (один шаг — сразу инициализация)
Rational::Rational(long long n, long long d) : num(n), den(d) {
    simplify();  // нормализация дроби
}

// Для const-полей и ссылок — только список инициализации!
class Foo {
    const int id;
public:
    Foo(int i) : id(i) {}  // обязательно!
};

Оператор присваивания

Не путай с конструктором копирования! Оператор присваивания работает когда объект уже создан:

class_array/array.cpp — оператор присваивания
Array& Array::operator=(const Array& arr) {
    // 1. Проверка самоприсваивания: a = a
    if (this == &arr) return *this;

    // 2. Освобождаем старую память
    delete[] ptr;

    // 3. Копируем данные
    size     = arr.size;
    capacity = arr.capacity;
    ptr      = new int[capacity];
    for (int i = 0; i < size; i++)
        ptr[i] = arr.ptr[i];

    // 4. Возвращаем *this для цепочек: a = b = c
    return *this;
}

Деструктор

Деструктор вызывается автоматически при выходе объекта из области видимости или при delete. Его задача — освободить ресурсы.

class_array/array.cpp
Array::~Array() {
    delete[] ptr;  // освобождаем динамическую память
    ptr = nullptr; // хорошая практика — обнулить указатель
}
Правило пяти (Rule of Five)
Если тебе нужен хотя бы один из: деструктор, конструктор копирования, оператор присваивания, конструктор перемещения, оператор перемещения — скорее всего нужны все пять. В простых случаях (без динамической памяти) полагайся на автоматически сгенерированные версии.

Когда вызываются конструктор и деструктор

Порядок вызовов
void foo() {
    Array a(5);      // КОНСТРУКТОР Array(int)
    {
        Array b = a;   // КОНСТРУКТОР КОПИРОВАНИЯ Array(const Array&)
    }                  // ДЕСТРУКТОР b — выход из блока
    Array* c = new Array(3);  // КОНСТРУКТОР, объект в куче
    delete c;          // ДЕСТРУКТОР c — явное удаление
}                      // ДЕСТРУКТОР a — выход из функции

Правило нуля

Если класс управляет только простыми данными (не указателями, не ресурсами) — не пиши деструктор вообще. Пусть компилятор делает всё сам. Используй std::vector, std::unique_ptr и т.д. вместо голых указателей.

chess/table.h — умные указатели вместо голых
class Table {
    // unique_ptr сам освободит память — деструктор писать не нужно!
    std::vector<std::unique_ptr<Figure>> pieces;
    std::vector<std::unique_ptr<Figure>> captured;
public:
    Table();
    Table(const Table&);  // нужен, т.к. unique_ptr не копируется
};

5 вопросов
Вопрос 1

Что произойдёт при выполнении: Array b = a; если конструктор копирования не написан?

Компилятор сгенерирует конструктор копирования, который скопирует поля побитово. Указатель ptr в обоих объектах будет указывать на один блок. При удалении первого объекта второй получит висячий указатель.
Вопрос 2

Когда вызывается деструктор для объекта, созданного на стеке?

Объекты на стеке уничтожаются автоматически при выходе из блока {}, в котором они объявлены. Это гарантировано языком C++.
Вопрос 3

Зачем в операторе присваивания проверяют if (this == &arr)?

При a = a без проверки: сначала освобождается ptr, потом пытаемся скопировать данные из arr.ptr — но это тот же самый удалённый ptr! Результат — undefined behavior.
Вопрос 4

Что такое список инициализации конструктора?

Список инициализации идёт между ) и { конструктора через двоеточие. Это единственный способ инициализировать const-поля и поля-ссылки. Также эффективнее, чем присваивание в теле.
Вопрос 5

В каком случае достаточно использовать "Правило нуля" (не писать деструктор)?

Если класс хранит только объекты с правильными деструкторами (vector, string, unique_ptr и т.д.), то не нужно писать деструктор, конструктор копирования и оператор присваивания — компилятор сгенерирует правильные версии.
