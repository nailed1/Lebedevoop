Тема 08

Связные списки

Динамическая структура данных — шаблонный связный список LineList<T> из репозитория.

Что такое связный список

Связный список — это цепочка узлов (элементов), где каждый узел хранит данные и указатель на следующий узел. В отличие от массива, элементы не расположены подряд в памяти.

ОперацияМассив (Array)Связный список
Доступ по индексуO(1) — быстроO(n) — надо пройти
Вставка в началоO(n) — сдвигO(1) — быстро
Удаление из началаO(n) — сдвигO(1) — быстро
Использование памятиПлотное+указатель на каждый элемент

Структура элемента списка

class_list_array/LineList.h — элемент
template<class T>
class LineListElem {
private:
    T data;                   // полезная нагрузка
    LineListElem* next;        // указатель на следующий

public:
    LineListElem(const T& d) : data(d), next(nullptr) {}

    // Только константный доступ к данным снаружи
    const T& getData() const { return data; }
    T&       getData()       { return data; }

    // next — доступен только классу LineList через friend
    LineListElem* getNext() { return next; }

    friend class LineList<T>;  // список может менять next напрямую
};

Структура самого списка

class_list_array/LineList.h — список
template<class T>
class LineList {
private:
    LineListElem<T>* start;  // указатель на первый элемент
    LineListElem<T>* tail;   // указатель на последний (для быстрого добавления)
    int length;               // количество элементов

public:
    LineList() : start(nullptr), tail(nullptr), length(0) {}
    ~LineList();

    void insertFirst(const T& data);
    void insertLast(const T& data);
    void insertAfter(LineListElem<T>* ptr, const T& data);
    void deleteFirst();
    void deleteAfter(LineListElem<T>* ptr);

    int               getLength() const { return length; }
    LineListElem<T>* getStart() { return start; }
};

Реализация операций

Вставка в начало — O(1)

insertFirst — вставка в начало
template<class T>
void LineList<T>::insertFirst(const T& data) {
    LineListElem<T>* newElem = new LineListElem<T>(data);

    if (start == nullptr) {
        // Список пустой — новый элемент и первый, и последний
        start = tail = newElem;
    } else {
        newElem->next = start;  // новый элемент указывает на старый первый
        start = newElem;        // новый элемент стал первым
    }
    length++;
}

Вставка в конец — O(1)

insertLast — вставка в конец
template<class T>
void LineList<T>::insertLast(const T& data) {
    LineListElem<T>* newElem = new LineListElem<T>(data);

    if (tail == nullptr) {
        start = tail = newElem;
    } else {
        tail->next = newElem;  // старый последний указывает на новый
        tail = newElem;        // новый стал последним
    }
    length++;
}

Деструктор — освобождение всех узлов

~LineList — освобождение памяти
template<class T>
LineList<T>::~LineList() {
    LineListElem<T>* current = start;
    while (current != nullptr) {
        LineListElem<T>* next = current->next;  // сохраняем следующий
        delete current;                          // удаляем текущий
        current = next;                           // переходим к следующему
    }
}

Обход списка

Обход через getNext()
LineList<int> list;
list.insertLast(10);
list.insertLast(20);
list.insertLast(30);

// Обход: начинаем с start, идём по next
for (auto* p = list.getStart(); p != nullptr; p = p->getNext()) {
    std::cout << p->getData() << " ";  // 10 20 30
}

Ключевые ООП паттерны в списке

  • friend class — LineList<T> является другом LineListElem<T>, может менять приватный next
  • Шаблон — один код для любого типа данных
  • RAII — деструктор освобождает всю цепочку узлов
  • Инкапсуляция — внешний код не может напрямую менять next

Тест для самопроверки

5 вопросов
Вопрос 1

Какова сложность вставки в начало связного списка?

В связном списке вставка в начало — O(1): создаём новый узел, его next = старый start, start = новый узел. Никаких сдвигов (в отличие от массива, где вставка в начало O(n)).
Вопрос 2

Почему LineListElem объявляет friend class LineList<T>?

Поле next — приватное. Снаружи его нельзя изменить. Но класс LineList должен менять next при вставке/удалении. Friend-объявление даёт доступ только ему, не открывая поле для всех.
Вопрос 3

Зачем в LineList хранится и указатель start, и указатель tail?

Без указателя tail вставка в конец требовала бы прохода по всему списку O(n). С tail — мы сразу знаем последний элемент и добавляем за O(1).
Вопрос 4

В деструкторе ~LineList() почему нужно сохранять next перед удалением текущего узла?

После delete current память освобождена. Обращение к current->next было бы обращением к удалённой памяти — undefined behavior. Поэтому сначала сохраняем next, потом удаляем узел.
Вопрос 5

Чем циклический список LineListCycle отличается от обычного?

В циклическом списке tail->next == start. Это позволяет бесконечно обходить круг — что нужно для задачи Иосифа. Важно: при обходе надо следить за условием остановки, иначе бесконечный цикл.
