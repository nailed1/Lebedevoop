Тема 01

Классы и инкапсуляция

Как объединить данные и поведение в одну сущность, и зачем скрывать внутреннее устройство объекта от внешнего мира.

Что такое класс

Класс — это тип данных, который ты создаёшь сам. Он описывает:

  • Состояние — поля (переменные-члены)
  • Поведение — методы (функции-члены)

Объект — это конкретный экземпляр класса (как переменная обычного типа).

Инкапсуляция

Принцип сокрытия внутренних деталей реализации и предоставления доступа к объекту только через публичный интерфейс (методы). Это защищает данные от случайного изменения и позволяет менять реализацию, не ломая код снаружи.

Правило по умолчанию
В class все члены по умолчанию private. В struct — public. Это единственное отличие между ними в C++.

Пример из репозитория: класс Rational

Файл class_Rational/rational.h — отличный пример инкапсуляции: числитель и знаменатель скрыты, наружу торчит только интерфейс.

class_Rational/rational.h
// Поля скрыты — нельзя напрямую поменять знаменатель на 0
class Rational {
private:
    long long num;   // числитель
    long long den;   // знаменатель (всегда > 0)
    void simplify(); // сокращение дроби — только для внутреннего использования

public:
    // Конструкторы — публичный вход в объект
    Rational(long long n = 0, long long d = 1);

    // Геттеры — безопасный доступ к данным
    long long getNum() const { return num; }
    long long getDen() const { return den; }

    // Арифметика через операторы
    Rational& operator+=(const Rational& r);
    Rational  operator+(const Rational& r) const;
    // ... и т.д.

    // Явное преобразование в double
    explicit operator double() const { return (double)num / den; }
};

Почему den нельзя трогать напрямую? Потому что класс всегда поддерживает инвариант: den > 0. Если бы поле было публичным, кто угодно мог бы написать r.den = 0 и получить деление на ноль.

Пример: класс Array

Файл class_array/array.h — динамический массив со скрытым указателем на память:

class_array/array.h
class Array {
private:
    int* ptr;       // указатель на данные — наружу не торчит!
    int  size;      // текущий размер
    int  capacity;  // выделенная ёмкость

    void increaseCapacity(int newCapacity); // внутренний метод

public:
    Array();                        // конструктор по умолчанию
    Array(int size);                 // конструктор с размером
    Array(const Array& arr);        // конструктор копирования
    ~Array();                       // деструктор — освобождение памяти

    int  getSize() const;          // безопасный доступ к размеру
    int& operator[](int index);   // доступ к элементу с проверкой
    void insert(int elem, int index);
    void remove(int index);
};

Геттеры и сеттеры

Геттер (getter) — публичный метод для чтения приватного поля. Сеттер (setter) — для записи, но с проверкой.

Пример геттера и сеттера
class DateTime {
private:
    int year, month, day;

public:
    int getYear()  const { return year; }
    int getMonth() const { return month; }
    int getDay()   const { return day; }

    // Сеттер с валидацией — нельзя поставить месяц = 99
    void setMonth(int m) {
        if (m < 1 || m > 12)
            throw std::invalid_argument("Неверный месяц");
        month = m;
    }
};
Типичная ошибка
Не делай сеттеры для всех полей подряд — это разрушает инкапсуляцию. Поле должно меняться только если это логически обоснованно. Если поле нельзя менять после создания — не делай сеттер вообще.

Статические члены класса

Статические поля и методы принадлежат классу в целом, а не конкретному объекту:

Пример из class_Rational/rational.cpp
class Rational {
private:
    // Статический вспомогательный метод — не нужен экземпляр
    static bool will_add_overflow(long long a, long long b);
    static bool will_mul_overflow(long long a, long long b);

public:
    // Статический публичный метод — фабричный метод или утилита
    static Rational fromDouble(double d);
};

const-методы

Метод помечается const, если он не изменяет состояние объекта. Это позволяет вызывать его на const-объектах и сигнализирует читателю кода о намерениях:

const-методы
class Rational {
public:
    long long getNum() const;  // ← не меняет объект
    Rational operator+(const Rational& r) const; // ← не меняет this

    Rational& operator+=(const Rational& r); // ← меняет this, не const!
};

// Можно вызывать const-методы на const-объектах:
const Rational r(1, 2);
r.getNum();   // OK
r += ...;      // Ошибка компиляции! += не const

Тест для самопроверки

5 вопросов
Вопрос 1

Какой спецификатор доступа используется по умолчанию в class?

В class все члены по умолчанию private. В struct — public.
Вопрос 2

Зачем поле den в классе Rational сделано приватным?

Инкапсуляция защищает инварианты класса. Знаменатель всегда должен быть > 0, и это гарантируется тем, что менять его можно только через методы класса, которые проверяют корректность.
Вопрос 3

Что означает ключевое слово const после объявления метода: int getSize() const;?

const после метода означает, что this внутри метода имеет тип const T* — поля нельзя изменить. Такой метод можно вызывать на const-объектах.
Вопрос 4

Чем static-метод отличается от обычного метода класса?

Статические методы принадлежат классу, а не объекту. У них нет неявного параметра this, поэтому они не могут обращаться к нестатическим полям напрямую.
Вопрос 5

Что произойдёт при попытке обратиться к private-полю класса извне?

Нарушение доступа — это ошибка на этапе компиляции, не runtime. Компилятор проверяет права доступа статически.
