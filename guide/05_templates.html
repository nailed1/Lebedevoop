Тема 05

Шаблоны (Templates)

Обобщённое программирование: пишешь один раз, работает для любого типа.

Зачем нужны шаблоны

Представь, что нужно написать класс "Точка" для int, потом для float, потом для double. Без шаблонов — три одинаковых класса с разными именами. С шаблонами — один класс Point<T>, который работает для любого типа.

Шаблон (Template)

Параметризованный класс или функция. Параметр — тип (или значение). Компилятор генерирует конкретный код при каждом использовании с новым типом.

Шаблонный класс Point

Из geometrical_figures/figures.h:

geometrical_figures/figures.h
// template — T это параметр типа
template<typename T>
class Point {
public:
    T x, y;
    Point(T x, T y) : x(x), y(y) {}

    // Метод шаблонного класса
    double distanceTo(const Point<T>& other) const {
        double dx = x - other.x;
        double dy = y - other.y;
        return sqrt(dx*dx + dy*dy);
    }
};

// Использование — компилятор создаёт три разных класса:
Point<int>    pi(1, 2);
Point<float>  pf(1.5f, 2.5f);
Point<double> pd(3.14, 2.71);

Шаблонный класс + наследование

В репозитории шаблонные классы наследуют от нешаблонного базового класса — это позволяет хранить их в одном контейнере:

geometrical_figures/figures.h
// Нешаблонный базовый класс (интерфейс)
class Figure {
public:
    virtual double calc_area()      const = 0;
    virtual double calc_perimeter() const = 0;
    virtual ~Figure() = default;
};

// Шаблонный производный класс
template<typename T>
class Circle : public Figure {
private:
    Point<T> center;
    double   radius;
public:
    Circle(Point<T> c, double r) : center(c), radius(r) {}
    double calc_area()      const override { return M_PI * radius * radius; }
    double calc_perimeter() const override { return 2 * M_PI * radius; }
};

// Благодаря нешаблонному Figure, можно хранить все фигуры вместе:
std::vector<Figure*> shapes;
shapes.push_back(new Circle<double>({0,0}, 5.0));
shapes.push_back(new Rectangle<int>({0,0}, {4,3}));

Шаблонный связный список LineList<T>

Файл class_list_array/LineList.h — полноценный шаблонный контейнер:

class_list_array/LineList.h
// Элемент списка — тоже шаблонный
template<class T>
class LineListElem {
private:
    T data;
    LineListElem* next;
public:
    LineListElem(const T& d) : data(d), next(nullptr) {}
    const T& getData() const { return data; }
    LineListElem* getNext() { return next; }

    friend class LineList<T>;  // список может менять next
};

template<class T>
class LineList {
private:
    LineListElem<T>* start;
    LineListElem<T>* tail;
    int length;
public:
    LineList() : start(nullptr), tail(nullptr), length(0) {}
    ~LineList();

    void insertFirst(const T& data);
    void insertLast(const T& data);
    void deleteFirst();
    LineListElem<T>* getStart() { return start; }
};

// Использование для разных типов:
LineList<int>         intList;
LineList<std::string> strList;
LineList<Rational>    ratList;

Шаблонный Polygon — формула Гаусса

geometrical_figures/figures.cpp — Polygon
template<typename T>
double Polygon<T>::calc_area() const {
    int n = vertices.size();
    if (n < 3) return 0;

    double area = 0;
    // Формула Гаусса (shoelace formula)
    for (int i = 0; i < n; i++) {
        int j = (i + 1) % n;
        area += (double)vertices[i].x * vertices[j].y;
        area -= (double)vertices[j].x * vertices[i].y;
    }
    return std::abs(area) / 2.0;
}

// Явная инстанциация — помогает компилятору
template class Polygon<int>;
template class Polygon<float>;
template class Polygon<double>;

Шаблоны функций

Шаблонная функция
// Универсальный swap — без шаблона пришлось бы писать для каждого типа
template<typename T>
void mySwap(T& a, T& b) {
    T temp = a;
    a = b;
    b = temp;
}

int x = 1, y = 2;
mySwap(x, y);          // компилятор выведет T = int
mySwap<double>(x, y);  // явное указание типа
Где размещать реализацию шаблона
Реализация шаблонных классов и функций обычно размещается в .h-файле, а не в .cpp. Компилятор должен видеть полный код шаблона при инстанциации. Исключение — явная инстанциация (template class Foo<int>;) в .cpp файле.

typename vs. class в шаблонах

Оба ключевых слова означают одно и то же при объявлении параметра типа:

typename и class — эквивалентны для параметров типа
template<typename T> class Foo {};  // современный стиль
template<class T>    class Bar {};  // старый стиль, тоже корректно

5 вопросов
Вопрос 1

Когда компилятор генерирует код для шаблонного класса?

Шаблон сам по себе — это не код, а рецепт. Компилятор генерирует конкретный класс при каждой инстанциации: Point<int>, Point<double> — это два разных класса с одинаковой структурой.
Вопрос 2

Зачем в репозитории класс Figure — нешаблонный, а Circle<T> — шаблонный?

Это умный дизайн: Circle<int> и Circle<double> — это разные типы. Если бы базовый класс тоже был шаблонным, нельзя было бы их смешивать. Нешаблонный базовый класс служит общим интерфейсом для полиморфного использования.
Вопрос 3

В каком файле обычно размещается реализация шаблонного класса?

Шаблонный код должен быть виден компилятору в момент инстанциации. Поэтому реализация помещается прямо в .h или в .tpp который включается из .h. Исключение — явная инстанциация в .cpp, как в geometrical_figures/figures.cpp.
Вопрос 4

Что означает template class Polygon<double>; в .cpp файле?

Явная инстанциация (explicit instantiation) говорит компилятору сгенерировать весь код класса для указанного типа прямо здесь. Это позволяет держать реализацию в .cpp файле, а не в .h.
Вопрос 5

В чём разница между шаблонным и виртуальным полиморфизмом?

Статический полиморфизм (шаблоны): типы подставляются при компиляции, накладные расходы нулевые. Динамический полиморфизм (виртуальные функции): выбор реализации в runtime через vtable, небольшие накладные расходы. Репозиторий использует оба подхода.
